# CalDAV Codeforces Bot

[English](README.md) | [Русский](README_RU.md)

Telegram-бот, который отслеживает контесты [Codeforces](https://codeforces.com), анонсирует их пользователям, создаёт события в их **CalDAV-календарях** (Яндекс или любой сторонний CalDAV-сервер) и рассылает напоминания перед началом.

## Возможности

- **Отслеживание контестов** — бот опрашивает Codeforces API и анонсирует новые предстоящие контесты всем пользователям.
- **«Буду участвовать»** — одно нажатие создаёт контест событием во всех активных CalDAV-календарях пользователя.
- **Умное создание событий** — перед записью бот проверяет, не существует ли событие (по UID) и не пересекается ли оно с другими событиями календаря (повторяющиеся события раскрываются локально).
- **Напоминания** — настраиваемые интервалы (по умолчанию: 60 / 15 / 5 минут до начала) с дедупликацией: каждое напоминание срабатывает ровно один раз.
- **Яндекс и произвольный CalDAV** — подключение Яндекс-аккаунта (почта + пароль приложения) или любого CalDAV-сервера (URL + логин + пароль) через пошаговый мастер в чате с выбором календаря.
- **Шифрование паролей** — пароли календарей шифруются Fernet; смена ключа шифрования детектируется, пользователю предлагается переподключить календарь.
- **Защита от SSRF** — локальные / loopback / приватные адреса CalDAV отклоняются, если это явно не разрешено.
- **Админ-панель** — админы могут эмулировать контест (название, время начала, длительность) и получить отчёт о доставке анонса.

## Как это работает

```
Codeforces API ──▶ парсер (каждые 10 минут по умолчанию) ──▶ SQLite (Contest)
                              │
                              ▼
                   анонс всем пользователям
                              │
                      «Буду участвовать»
                              │
        календари пользователя (CalDAV) ◀── создание события (UID cf-contest-{id})
                              │
      планировщик напоминаний (каждые 10 с) ──▶ сообщения в выбранные интервалы
```

- Время контестов и событий хранится как naive UTC; всё пользовательское время отображается в **Europe/Moscow** (МСК).
- Напоминания дедуплицируются через лог уведомлений; записи старше 30 дней автоматически удаляются.
- От гонок защищают per-user блокировки и повторные проверки (двойные отправки, одновременное подключение календарей).

## Требования

- Python **3.12+** (или Docker 29+ / Docker Compose v2+)

## Быстрый старт

### 1. Настройка

```bash
cp .env.example .env
```

Заполните обязательные значения:

| Переменная | Обязательно | Описание |
|---|---|---|
| `BOT_TOKEN` | да | Токен Telegram-бота от [@BotFather](https://t.me/BotFather) |
| `SECRET_KEY` | да | Fernet-ключ для шифрования паролей календарей. Сгенерировать: `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"` |
| `ADMIN_IDS` | нет | Telegram ID админов через запятую |
| `DATABASE_URL` | нет | SQLAlchemy DSN (по умолчанию `sqlite+aiosqlite:///bot.db`) |
| `PARSE_INTERVAL_SECONDS` | нет | Интервал опроса Codeforces (по умолчанию `600`) |
| `REMIND_INTERVAL_SECONDS` | нет | Интервал проверки напоминаний (по умолчанию `10`) |
| `ALLOW_LOCAL_CALDAV` | нет | Разрешить CalDAV-серверы на локальных/приватных адресах (по умолчанию `false`) |

> **Не меняйте `SECRET_KEY`.** Потеря ключа делает сохранённые пароли календарей нерашифровываемыми — пользователям придётся переподключить календари.

### 2. Запуск

**Через Docker Compose (рекомендуется):**

```bash
docker compose up -d --build
docker compose logs -f
```

Данные сохраняются в named volume `bot-data` (SQLite в `/data/bot.db` внутри контейнера). В Docker значение `DATABASE_URL` из `.env` автоматически переопределяется на `sqlite+aiosqlite:////data/bot.db`.

**Без Docker:**

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python main.py
```

## Использование

### Для пользователей

- `/start` — главное меню: подключение календаря, настройка уведомлений.
- **Подключение календаря** — выберите Яндекс (пошаговый гайд по паролю приложения показывается в чате) или сторонний CalDAV-сервер; бот проверит учётные данные, покажет список доступных календарей и предложит выбрать. До 10 календарей на пользователя; каждый можно включить/выключить или удалить в настройках.
- **Уведомления** — интервалы от 5 минут до 1 недели (до 10 на пользователя).
- **Анонсы** — новые контесты приходят с кнопкой «🔥 Буду участвовать», которая создаёт событие во всех активных календарях и показывает результат по каждому календарю (создано / уже есть / пересечения / ошибки).
- `/cancel` — прервать любой запущенный мастер настройки.

### Для админов

- `/admin` — админ-панель.
- `/create` — создание эмулированного контеста (название, время начала по МСК, длительность) с анонсом всем пользователям и отчётом о доставке.

Админы исключены из анонсов, напоминаний и подключения календарей.

## Безопасность

- Пароли календарей хранятся зашифрованными (Fernet) и никогда не показываются пользователю обратно.
- Для каждого календаря хранится отпечаток `SECRET_KEY`; при смене ключа расшифровка отклоняется и пользователю предлагается переподключить календарь вместо тихой ошибки.
- CalDAV-адреса, указывающие на localhost / приватные сети, отклоняются, если не установлен `ALLOW_LOCAL_CALDAV=true`.
- CalDAV по HTTP (без TLS) требует явного подтверждения.

## Известные ограничения

- События календаря **только создаются** — если Codeforces перенесёт контест, событие в календаре не обновится; также нет сценария «отписаться», удаляющего события.
- Состояние мастеров (FSM) хранится в памяти — незавершённая настройка теряется при перезапуске бота.
- Поиск пересечений загружает все события календаря (без серверного фильтра по времени), что может быть медленным на очень больших календарях.
- Анонс помечается как отправленный, даже если доставка части пользователей не удалась (например, бот заблокирован) — доставка best-effort.
- Напоминания и анонсы админам не рассылаются — это осознанное решение.
